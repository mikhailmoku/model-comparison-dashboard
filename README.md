# LLM Comparison Dashboard

Streamlit-дашборд для сравнения открытых LLM (через Ollama) по скорости ответов на одинаковых промптах.

## Что делает

- Отправляет один промпт нескольким моделям одновременно
- Замеряет **time-to-first-token**, общее время генерации, **токенов/сек**
- Визуализирует результаты в таблице и на графике
- Хранит историю прогонов в рамках сессии и считает агрегированную статистику

## Стек

Python, Streamlit, Ollama (локальный inference), pandas

## Запуск

```bash
# Я на таких моделях запускал, вы можете использовать любые другие установленные у вас в ollama
ollama pull llama3.2:1b
ollama pull phi3:mini
ollama pull gemma2:2b


pip install -r requirements.txt


streamlit run app.py
```

## Методология измерений

- **Время ответа** — от отправки запроса до получения финального токена (`time.perf_counter`)
- **Time-to-first-token** — доступно только в режиме `stream=True`, отражает "отзывчивость" модели
- **Токенов/сек** — `eval_count` из ответа Ollama, делённый на общее время

## Ограничения

- "Стоимость" для локальных моделей не считается в деньгах — прокси для cost/compute это скорость и размер модели. Честное сравнение цены можно добавить, подключив платные API (OpenAI/Anthropic) наравне с локальными моделями
- Результаты сильно зависят от железа, на котором крутится Ollama

## Результаты

| Модель      | Токенов/сек | Время/сек |
| ----------- | ----------- | --------- |
| llama3.2:1b | ~26.35      | 4.05      |
| phi3:mini   | ~21.68      | 12.74     |
| gemma2:2b   | ~22.5       | 7.25      |

**Вывод:**

llama3.2:1b — самая быстрая модель как по скорости генерации (~26.35 токенов/сек), так и по общему времени ответа (4.05 сек). Ожидаемо, учитывая её минимальный размер (1B параметров) среди всех трёх моделей.

gemma2:2b заняла второе место с близкой скоростью генерации к phi3:mini (~22.5 ток/сек), но при этом ответила почти в 2 раза быстрее по общему времени (7.25 сек против 12.74 сек) — значит либо сгенерировала заметно более короткий ответ, либо у phi3:mini в этом прогоне была задержка на старте.

phi3:mini показала самое долгое общее время (12.74 сек) при этом самую низкую скорость генерации (~21.68 ток/сек) — минимальный результат по обеим метрикам. Это может объясняться либо генерацией более длинного/развёрнутого ответа на тот же промпт, либо накладными расходами на загрузку модели в память при первом обращении (cold start).

Итого: для сценариев, где критична скорость отклика (интерактивные чат-боты, live-демо), llama3.2:1b — предпочтительный выбор среди протестированных моделей. Разница между gemma2:2b и phi3:mini по общему времени существенная (почти в 2 раза) при сопоставимой скорости генерации токенов — это говорит о том, что итоговое время ответа зависит не только от скорости модели, но и от длины сгенерированного текста, и её стоит учитывать отдельно как метрику в будущих замерах.
